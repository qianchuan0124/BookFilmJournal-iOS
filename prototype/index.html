已确认的设计决策

015 Tab，不做中央「＋」

唯一需要「新建」的是记录，但同步豆瓣才是核心动作；中央按钮会误导成记账式唯一入口。新增放在记录页标题栏，同步固定在记录页右上。

记录 / 豆列 / 计划 / 报告 / 设置，与桌面 7 个页面的信息层级一一对应。

02海报墙 3 列

桌面 5 列在 390pt 宽度下只能显示 2 列半；3 列能同时保留日期分组、标题两行与星级，接近豆瓣 App 的浏览手感。

封面 2:3，卡片内显示评分角标、标题 2 行、时长/字数与星级。

03详情与编辑用半屏浮层

浏览时点卡片先看详情，不离开海报墙；详情里再进编辑。浮层可下拉关闭，返回时保留列表滚动位置。

长评在浮层内滚动，操作固定为豆瓣页面 / 换封面 / 删除。

04本地优先规则显式呈现

桌面「本地改过的日期、评分、短评不被覆盖」在手机上容易被忽略。用封面右上金点 + 编辑页说明 + 「恢复豆瓣原始时间」开关把规则讲清楚。

金点 = 本地修改；开关关闭时同步不会覆盖本地值。

05同步方式与范围一次选择

三种同步方式在手机上用单选行呈现，默认「增量 + 新增并移除」；观影 / 读书 / 豆列可分别勾选，避免每次全量。

同步结果在同一浮层展示新增 / 更新 / 移除与耗时。

06报告复用桌面 HTML

报告版式复杂（TOP 5、海报墙、日历、短评），用 SwiftUI 重写成本高且容易走样。iOS 生成同一份 HTML，用 WKWebView 预览，PNG 由 WebView 快照导出。

已确认：PNG 用 WebView 快照，超过 12000px 自动分段；HTML 始终保留。

07云同步走「文件」里的 iCloud Drive

不接 CloudKit：快照是整库 SQLite，与桌面共用同一套「同步目录 + latest.json + 多份快照」逻辑，Mac 与 iPhone 可互相恢复。

每台设备 3 份自动 + 2 份手动；恢复前先备份本机数据库。

08字数统计不依赖 Calibre

iOS 无法运行 Calibre。直接解析「文件」中的 EPUB / TXT / DOCX；MOBI / AZW3 提示先转换格式。手动字数始终优先。

统计结果写回记录，并随快照同步到其他设备。

09回收站与彻底删除

回收站放在设置内（低频但重要），记录 / 豆列 / 计划共用。彻底删除留标记，避免下次同步被加回，也能随 Excel 导入到其他设备。

已确认：留在设置内，不做一级入口；删除 Toast 提供「撤销」。

10深色优先，但跟随系统

桌面主打暗色 + 金色；移动端默认跟随系统，设置里可强制浅色 / 深色。海报本身是彩色，暗色模式只换界面与描边，不改变封面。

主色 #E8B65C；已读 #688A4A，想看 #B86F30，统计 #2E8775；深色为墨蓝 + 香槟金。

11登录：WKWebView + Keychain

豆瓣没有 OAuth 回调，Safari 登录后的 Cookie 也无法交给 App。改为 App 内 WKWebView 承载豆瓣登录页，成功后读取 Cookie 存本机 Keychain；Safari 打开与粘贴 Cookie 仅作兜底。

默认 App 内扫码/账号登录；Safari 兜底需手动复制 Cookie，两者都不上传服务器。

12探索空间：GitHub 下发 + 连通性

远端站点列表由 GitHub 的 sites.json 下发；本地可新增站点并标「本地」，拉取不覆盖。左上角「拉取」更新列表，「刷新」并发探测连通性，绿勾 / 红叉对应可达与不可达。点链接复制完整地址并 Toast。

远端配置只读 + 本地缓存；拉取失败沿用旧配置；长链接按可用宽度自动省略。

13详情页「资源」：searchUrl 直达

已看与想看的记录详情都放同一个「资源」入口。配置里的 searchUrl 支持 {title}，有模板就带标题打开站内结果页；没有模板或站点异常则打开首页，豆瓣条目兜底。

只做 URL 模板跳转，不注入 Cookie、不模拟站内表单。

14布局与字号范式

全屏页固定头 250pt（约 30%）：状态栏、标题、筛选、摘要不滚动；下方滚动区约 70%，底部统一 24pt。正文 16，行标题 16，辅助 14，元信息 12.5，标签 10.5–12；3 列海报标题 13.5 为密度例外。

新页面统一 .page-head + .body.scroll；浮层统一 .sheet-head + .sheet-body；不要把筛选器或摘要放进滚动区。
